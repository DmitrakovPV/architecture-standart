| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
|F-1  | Сайт: просмотр списка депозитов с актуальными ставками. Подача заявки новым клиентом (ФИО, телефон) | Первичный канал привлечения. Не требует авторизации.             |
|F-2   | Кол-центр: просмотр заявок с сайта и возможность предложить особые условия.|   Требуется интеграция Системы КЦ с новой базой заявок (или напрямую с АБС)|
|F-3   | Интернет-банк: просмотр базовых и персонализированных ставок. Подача заявки| Требуется авторизация клиента. Персонализация требует запроса данных из АБС|
|F-4   | Интернет-банк: подтверждение операции подачи заявки с помощью СМС-кода.| Требуется генерация и валидация одноразовых паролей (OTP) |
|F-5   | СМС-уведомления клиенту после подтверждения ставки бэк-офисом и после открытия депозита| Асинхронный процесс. Не должен блокировать основной поток подачи заявки|
|F-6  | Бэк-офис: обработка заявки, подтверждение условий депозита в АБС | MVP предполагает полуавтоматический режим с участием человека |
|F-7  | Управление ставками: перенос ведения ставок из XLS-файлов в систему (предпочтительно АБС) с доступом для бэк-офиса депозитов и кредитов | Исключение ручного труда и Excel. Решает проблему актуальности и прозрачности ставок |
|F-8  | Шифрование трафика (HTTPS/TLS) при передаче чувствительных данных с сайта и из ИБ | Защита ПДн и финансовых данных |
| U   | Удобство использования (Usability) |              |
|U-1  | Интерфейс должен соответствовать корпоративной системе дизайна                                | Снижение порога входа для возрастных клиентов, поддержка бренда             |
|U-2 | Отклик интерфейса на все операции — миллисекунды   |   Необходимо кэширование справочных данных, чтобы избежать задержек, как в текущих платежах           |
| R   | Надёжность (Reliability)           |              |
| R-1   | Доступность сервисов 24/7 с уровнем SLA 99,9%    |   Критично для онлайн-каналов. Требует отказоустойчивой архитектуры           |
|   R-2  |Отказоустойчивость ИБ: при сбое основного ЦОД сервисы ИБ должны оставаться доступными |Текущее состояние не отвечает требованию. Требуется геораспределение             |
| P   | Производительность (Performance)   |              |
| P-1    | Горизонтальное масштабирование ИБ и распределение нагрузки между серверами и ЦОД  |Необходимо для обработки пиковых нагрузок  |
| P-2    | Изоляция нагрузки: онлайн-подача заявок не должна ронять АБС                                |АБС перегружена. Прямые запросы к ней приведут к деградации всей банковской системы              |
| S   | Поддерживаемость (Supportability)  |              |
| S-1   | Реализация СМС-функционала силами команды банка                                | Снижение зависимости от вендора, ускорение Time-to-Market для фич             |
| S-2    |Использование существующих технологий и СУБД (MS SQL, Oracle) и экспертизы команды | Снижение стоимости владения и рисков внедрения новых стеков |
| S-3   | Перевод модуля ИБ (в части депозитов) на микросервисную архитектуру                              |Необходимо для гибкости, независимого деплоя и будущей интеграции с Kafka |
|S-4    | Подготовка документации для дальнейшего расширения системы | Обеспечение преемственности и масштабирования на кредитные продукты |
| +R  | + Ограничения (Restrictions)       |              |
| R-1    | Идентификация новых клиентов только при личном визите в отделение                              | Законодательное требование. Сайт может только собирать лиды             |
| R-2   | Запрет на прямую интеграцию Интернет-банка с API/БД АБС в новом процессе                               | База данных АБС перегружена. Требуется слой промежуточного ПО             |
| R-3   | АБС масштабируется только вертикально | Ограничение платформы (Oracle). Нельзя рассчитывать на горизонтальное масштабирование ядра |
| R-4   | 	Текущая платформа ИБ несовместима с Kafka | Kafka — целевое решение на перспективу, но внедрение требует пересмотра архитектуры ИБ |
| R-5   | Новые технологии должны быть совместимы с MS SQL, Oracle и текущими платформами разработки | Минимизация технологического разнообразия |
